1 Core Concepts (Anas's Stack)

  • No Prometheus/Grafana: Hum modern stack use karenge!
  • Three Pillars: Observability 3 cheezon par mabni hai: Metrics (Numbers, CPU/RAM), Logs (Text, Errors), aur Traces (Request kahan kahan gayi aur kitna time liya).
  • OpenTelemetry (OTel): Yeh ek standard pipeline (Collector) hai jo app se data le kar kisi bhi dashboard ko bhej sakti hai. (Vendor-neutral).
  • Dashboards: Hum SigNoz ya Netdata use karenge jo modern aur fast hain, aur Coroot (eBPF based) jo automatically service map bana deta hai.

2 Hands-on Steps

  1. Cluster mein Netdata ya SigNoz deploy karein.
  2. Ek simple app (e.g. Node.js) ko OpenTelemetry (OTel) ke sath instrument karein taake wo traces generate kare.
  3. Dashboard mein ja kar "Golden Signals" check karein: Latency (speed), Traffic (requests), Errors, aur Saturation (CPU full).
  4. Native tools use karein: kubectl top nodes, kubectl logs, kubectl get events.
  5. Debugging ke liye Ephemeral Containers use karein: kubectl debug -it pod/my-app --image=busybox (App pod ke andar ghus kar usko debug karna bina pod restart kiye).

3 Best Practices (Pro Tips)

  • Hamesha Structured Logs (JSON format) use karein taake search karna asaan ho.
  • OpenTelemetry ko as a standard apnayen, is se aap kabhi kisi ek tool (vendor) ke mohtaj nahi rahenge.
  • Alert on Symptoms, not causes: Alert tab aana chahiye jab "User ka login fail ho raha hai" (Symptom), na ke tab jab "CPU 80% hai" (Cause).

Done-Check

  • Aapka live dashboard (SigNoz/Netdata) chal raha hai, aur aap ek request ki complete trace end-to-end dekh sakte hain!
