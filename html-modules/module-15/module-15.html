1 Analogy (Samajhne ke liye)

RBAC: "Role-Based Access Control" ka matlab hai "Kis ke paas kounse kamre ki chabi hai".

ServiceAccount: Aapka ID Card.

Role: Permission ki list (e.g. "Ye banda sirf Pods dekh sakta hai").

RoleBinding: Guard jo aapke ID Card ko us Role ke sath link kar ke entry deta hai.

2 Core Concepts

  • Role vs ClusterRole: Role sirf ek namespace mein kaam karta hai. ClusterRole pooray cluster mein kaam karta hai (jaise Nodes dekhna).
  • SecurityContext: Pod ko container ke level par secure karna. Jaise runAsNonRoot: true (container root user ban kar nahi chalega), ya read-only file system.
  • Pod Security Standards: K8s namespaces par labels laga kar hum enforce kar sakte hain ke koi bhi "Privileged" (khuli choot wala) pod na chal sakay (Baseline ya Restricted standards).

3 Hands-on Steps

  1. Ek limited ServiceAccount create karein.
  2. Ek Role banayen jo sirf Pods read (get, list) kar sakay aur usay RoleBinding ke zariye SA se jor dein.
  3. Test karein: kubectl auth can-i get pods --as=system:serviceaccount:default:my-sa.
  4. Ek Pod banayen jisme SecurityContext: runAsNonRoot: true ho, aur test karein.
  5. Ek namespace par pod-security.kubernetes.io/enforce: restricted ka label lagayen aur usme root pod chala kar fail hota dekhein.

4 Errors to Break + Fix

  • Forbidden (403): Agar aapke ServiceAccount ke paas Secrets dekhne ka Role nahi hai aur wo koshish kare, toh K8s API Forbidden error dega.
  • Pod rejected by Admission: Agar namespace restricted hai aur aapne root pod deploy kiya, toh pod banne se pehle hi API server usay reject kar dega.

5 Best Practices (Pro Tips)

  • Least Privilege: Apps ko utni hi permission dein jitni chahiye. Kabhi bhi apps ko `cluster-admin` mat banayen.
  • Hamesha containers ko runAsNonRoot chalayen.
  • Supply chain security ke liye apne Docker images ko scan zaroor karein (Trivy se) taake vulnerabilities K8s mein na aayen.

Done-Check

  • Aapka least-privilege ServiceAccount theek kaam kar raha hai aur privileged pod successfully block ho gaya! Cluster ab secure hai.
