1 Core Concepts

  • Cloud vs Bare-Metal: Jab aap AWS/GCP par type: LoadBalancer banate hain toh Cloud provider auto-IP de deta hai. Lekin local/bare-metal cluster mein yeh IP kon dega?
  • MetalLB: Yeh wo tool hai jo local clusters (jaise Multipass/Kubeadm) mein IP assign karne ka theka leta hai.
  • IP Address Pool: MetalLB ko ek range di jati hai (e.g. 192.168.x.50-100). Jab bhi koi naya LoadBalancer service banta hai, MetalLB is pool se ek IP nikal kar de deta hai.

2 Hands-on Steps

  1. Cluster mein MetalLB install karein (Manifests ya Helm ke zariye).
  2. Ek IPAddressPool create karein jo aapke host ke network subnet se match karti ho (jaise Multipass ka subnet).
  3. Ek L2Advertisement banayen taake ye IP addresses network mein announce (broadcast) ho sakein.
  4. Ek app deploy kar ke usay type: LoadBalancer Service ke through expose karein.
  5. kubectl get svc karein aur dekhein ke <pending> ki bajaye ek real external IP mil gaya hai!

3 Errors to Break + Fix

  • EXTERNAL-IP <pending>: Agar aapne MetalLB install nahi kiya, ya L2Advertisement banana bhool gaye hain, toh IP kabhi nahi milega aur status pending rahega.
  • IP pool overlaps: Agar aapne DHCP (router) ki IP range MetalLB ko de di, toh IP conflicts (clashes) aayenge aur internet masle karega.

4 Best Practices (Pro Tips)

  • MetalLB ke liye hamesha apne network ka ek aisa hissa (range) **dedicate** karein jo apka router auto-assign (DHCP) na kar raha ho.
  • Lab environments ke liye **L2 Mode** best aur sabse asaan hai (BGP mode complex networks ke liye hota hai).

Done-Check

  • Aapki Service ko ek asli External IP assign ho gaya hai jo aapke host (Laptop) ke browser se bilkul theek khul raha hai!
