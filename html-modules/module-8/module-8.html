1 Analogy (Samajhne ke liye)

HPA (Horizontal Pod Autoscaler): Restaurant (app) mein jitna zyada rush hoga, utne naye waiters (pods) hire kiye jayenge. Jab rush khatam, waiters fire (scale down) kar diye jayenge.

2 Core Concepts

  • metrics-server: Yeh component cluster ka CPU aur RAM usage read karta hai aur HPA ko btata hai. Iske baghair autoscaling nahi chalti!
  • HPA (Horizontal): Pods ki tadaad (count) barhata ya kam karta hai (scale out/in) CPU/mem ya custom metrics ke base par.
  • VPA (Vertical): Pods ko lamba karta hai (right-size a pod), yaani existing pod ki CPU/RAM limit barhata hai.
  • Cluster Autoscaler: Jab cluster mein pods ke liye jagah khatam ho jaye, toh yeh naye Nodes (Servers) add karta hai.
  • KEDA: Event-driven scaling (e.g. RabbitMQ mein 100 messages aayen toh 10 pods bana do).

3 Hands-on Steps

  1. Cluster mein metrics-server install karein.
  2. Ek app par CPU based HPA create karein (e.g. target 50% CPU).
  3. Load generate karein (jaise hey tool ya busy loop se).
  4. Watch karein (kubectl get hpa -w) ke kaise pods scale up hotay hain aur load khatam honay par dobara scale down hotay hain.

4 Errors to Break + Fix

  • HPA `unknown` targets: Agar kubectl get hpa mein target <unknown>/50% likha aye, iska matlab metrics-server missing hai ya misconfigured hai (Nested VMs mein aksar TLS flag fix karna parta hai).

5 Best Practices (Pro Tips)

  • HPA ke theek se kaam karne ke liye zaroori hai ke aapne Pod ki Requests lazmi set ki hon! (Q k percentage Requests par calculate hoti hai).
  • Autoscaling ko PodDisruptionBudget ke sath combine karein taake updates ke doran zero-downtime maintain rahay.
  • HPA aur VPA ko ek hi metric (jaise CPU) par kabhi mix na karein, warna dono apas mein larte rahenge!

Done-Check

  • Load dalnay par pods auto-scale (barh) gaye, aur load hatanay par wapas normal count par aa gaye. Autoscaling Mastered!
