Module 1

Pods, ReplicaSets, Deployments

Cluster setup hone ke baad, hum apne applications ko chalana shuru karte hain. Is module mein hum Kubernetes ke basic building blocks ko detail mein samjhenge.

Analogy: Pod = Ek worker. ReplicaSet = HR manager jo yeh ensure karta hai ke hamesha N workers kaam kar rahe hon. Deployment = Boss (General Manager) jo naye version ya updates laane ka poora process control karta hai bina kisi ko disturb kiye.

Hum Kya Seekhenge (Concepts)

  • Pod: Kubernetes mein deploy hone wala sab se chota unit, jiske andar containers (jaise Docker/Node.js) chalte hain.
  • ReplicaSet: Iska kaam sirf itna hai ke hamesha utne hi Pods chalte rahein jitne humne define kiye hain (High Availability).
  • Deployment: Yeh ReplicaSet ke upar ek layer hai jo rolling updates, scale up/down, aur rollback ko manage karta hai.
  • Labels aur Selectors: Inke zariye Kubernetes apas mein resources ko link karta hai (maslan, kon sa ReplicaSet kis Pod ko control karega).

Hands-on Steps

  1. Ek simple Nginx ya Node.js ka Deployment yaml file se create karein.
  2. Deployment ko scale up aur scale down karein (e.g., 3 pods se 5 pods).
  3. Application ka naya version update karein (Rolling update).
  4. Agar naya version theek kaam na kare, toh purane version par wapas jayen (Rollout undo).
  5. kubectl describe command use karke events ko check karein.

Errors (Jo hum break karke fix karenge)

Hum jaan boojh kar in issues ko create aur fix karenge:

  • Selector Mismatch: Jab Deployment ka selector Pod ke label se match nahi karta.
  • ImagePullBackOff: Jab hum jaan boojh kar galat Docker image name dete hain aur Kubernetes image download nahi kar pata.

Best Practices

  • Kabhi bhi direct Pod ya ReplicaSet na banayen, hamesha Deployment use karein taake updates manage ho sakein.
  • Labels ko systematically design karein (jaise app: frontend, env: production).

Done-Check

Yeh module tab complete hoga jab aap safely apne app ka naya version deploy aur rollback kar sakein, bina koi downtime face kiye.
