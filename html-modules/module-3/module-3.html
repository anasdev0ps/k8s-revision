Namespaces, Labels, Annotations

Jab ek hi Kubernetes cluster par boht si applications chalti hain, toh unhein organize aur alag (isolate) karna zaroori hota hai. Yeh module sikhata hai ke resources ko logical hisson mein kaise banta jaye aur unhein kaise dhoonda (select kiya) jaye.

Concept: Dev aur Prod ke Pods ek doosre ko dekh nahi sakte. Labels (yellow notes) Kubernetes ko identity batate hain, jabke Annotations (grey notes) insano ke liye extra information hoti hain.

Upar di gayi animation mein dekhein: Service sirf usi Pod ko apna traffic (green moving line) bhej rahi hai jiska Label env=prod match ho raha hai. Doosre Pod ko ignore kar diya gaya.

Analogy:
- Namespace: Ek ghar mein alag alag kamre (jaise Dev room aur Prod room). Dono kamron mein same naam ki cheezein ho sakti hain.
- Labels: Items par lagi "Sticky Notes" jinki madad se hum cheezon ko filter karte hain (e.g., "Find all boxes where env=prod").
- Annotations: Item ke sath lagi hui "Instruction Manual" jisme bari bari details likhi hoti hain jo sirf insano ko padhne ke liye hoti hain.

Hum Kya Seekhenge (Concepts)

  • Namespaces: Resources ko logical groups mein taqseem (divide) karna taake testing aur live environment apas mein takrayen na.
  • Labels: Chotay tags (jaise app=backend) jo Kubernetes use karta hai yeh pehchanne pehchanne ke liye ke konsa traffic kis Pod ko bhejna hai.
  • Annotations: Lambi details jo tools ya humans padhte hain magar Kubernetes unse filtering nahi karta.

Hands-on Steps

  1. Do naye namespaces banayein: kubectl create namespace dev aur kubectl create namespace prod.
  2. Ek Pod dev namespace mein deploy karein aur uspar label lagayen: env=dev.
  3. kubectl get pods -n dev -l env=dev command chala kar specific labeled pod ko dhoond kar dekhein.
  4. Pod ko describe karke uski annotations aur labels verify karein.

Errors (Jo hum break karke fix karenge)

Hum jaan boojh kar in issues ko create aur fix karenge:

  • Querying Wrong Namespace: Jab aap ghalat kamre (namespace) mein pod dhoondte hain toh "No resources found" ka error aata hai.
  • Typo in Labels: Agar Service ka selector aur Pod ka label match na karein (jaise animation mein dev pod ke sath hua), toh connection nahi banta.

Best Practices

  • Hamesha custom namespaces banayen, default namespace mein production workloads kabhi mat rakhein.
  • Ek standard labeling scheme follow karein (jaise app.kubernetes.io/name) taake future mein asani ho.
