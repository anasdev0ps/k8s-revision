Module 6: Scheduling

Affinity, Anti-Affinity, Taints, & Tolerations

Node A (GPU)
Taint: NoSchedule
Node B (Web)
Label: tier=frontend
Pod 1 Toleration Pass
Pod 2 nodeSelector: frontend
Pod 3 Anti-affinity (Avoid Pod 2)

1 Analogy (Samajhne ke liye)

nodeSelector: "Mujhe sirf isi table par baithna hai."

Affinity: "Main apne doston ke qareeb baithna pasand karunga." (preferred/required)

Anti-affinity: "Mujhe kisi aise shakhs ke sath mat bithana jisne perfume zyada lagaya ho." (Don't seat two of us together!)

Taint & Toleration: "Yeh table VIPs ke liye reserved hai (Taint). Sirf wohi baith sakte hain jinke paas VIP Pass (Toleration) ho."

2 Core Concepts

  • nodeSelector: Ek simple tareeqa jisse hum pod ko specific node par force karte hain.
  • Node Affinity: Advanced nodeSelector. Isme hum required (zaroori) aur preferred (ho jaye toh acha hai) rules laga sakte hain.
  • Pod Affinity / Anti-affinity: Ek pod ko doosre pod ke paas (affinity) ya door (anti-affinity) schedule karna.
  • Taints & Tolerations: Node par Taint lagane se pod wahan nahi jayega. Agar pod ko wahan bhejna hai toh pod mein Toleration add karni paregi.
  • Topology Spread Constraints: Pods ko nodes, zones, ya regions ke darmiyan evenly distribute (spread) karna taake High Availability (HA) milay.
  • nodeName: Pod ko directly kisi node par assign karna bina scheduler ke (rarely used).

3 Hands-on Steps

  1. Ek node ko label karein (e.g., tier=frontend), aur ek pod ko nodeSelector + node affinity ke zariye wahan force schedule karein.
  2. Pod anti-affinity: Replicas ko nodes ke across spread karein taake ek hi node par saare pods na aa jayen.
  3. Ek node ko Taint karein (kubectl taint nodes worker1 key=val:NoSchedule). Phir prove karein ke naye pods us node par nahi ja rahe. Aakhir mein pod mein Toleration add kar ke usay wahan schedule allow karein.
  4. Topology spread constraints apply karein High Availability ke liye.

4 Errors to Break + Fix

  • Over-constrained pod: Agar aapne aisi affinity laga di jiska koi node available hi nahi, toh pod Pending state mein phans jayega (no node fits).
  • Taint with no toleration: Agar sab nodes par Taint hai aur pod ke paas pass (toleration) nahi, toh pod unschedulable ho jayega.

5 Best Practices (Pro Tips)

  • Hamesha Anti-affinity aur Topology spread constraints use karein taake aapki app High Availability (HA) de sake (agar ek node gire toh saare pods down na hon).
  • Dedicated nodes (jaise GPU ya System nodes) ko humesha Taint karein taake normal web pods wahan ja kar resources zaya na karein.
  • Jab tak koi condition 100% zaroori na ho, hamesha preferred rules use karein bajaye required ke, taake scheduling asaan rahey.

Done-Check

  • Replicas correctly spread ho chuke hain, aur Tainted node par baghair toleration ke koi pod nahi ja raha. Aapne scheduling jeet li!
