Requests, Limits, QoS, & Quotas

Node (The Restaurant)
LIMIT: Max you can eat
REQUEST: Reserved Seat
App Pod
OOMKilled!

1 Analogy (Samajhne ke liye)

Request: "The seat you reserve." Yeh wo jagah (RAM/CPU) hai jo Kubernetes hamesha aapke liye bacha kar rakhega.

Limit: "The max you're allowed to eat before you're cut off." Agar aap Limit cross karenge, toh CPU throttle (slow) ho jayega, ya Memory zyada lenay par OOMKilled (Out of Memory Kill) kar diye jayenge!

2 Core Concepts

  • Requests: Kubernetes Scheduler use karta hai yeh decide karne ke liye ke pod ko kis Node par bhejna hai (taake wahan space ho).
  • Limits: Kubernetes Kubelet use karta hai enforce karne ke liye ke pod apni auqaat se zyada memory/cpu use na kare.
  • QoS Classes (Quality of Service):
    - Guaranteed: Jab Request == Limit (sabse safe).
    - Burstable: Jab Request < Limit (thori extra jagah mil sakti hai agar free ho).
    - BestEffort: Koi request/limit nahi (sabse pehle maaray jayenge agar node full ho gaya).
  • LimitRange: Ek default rule banata hai ke agar kisi ne limit nahi di toh usay auto kya limit milegi.
  • ResourceQuota: Poore Namespace par restriction lagata hai (e.g. is team ko total 10GB RAM se zyada nahi milegi).

3 Hands-on Steps

  1. Apne pod mein requests aur limits set karein.
  2. Force OOMKilled: Ek tiny memory limit (e.g. 10Mi) lagayen aur app ko memory khane dein. Dekhein kaise pod crash hota hai.
  3. CPU limit kam kar ke observe karein ke app slow (throttle) ho gayi hai magar crash nahi hui.
  4. Ek Namespace mein ResourceQuota apply karein aur us limit ko hit kar ke reject error dekhein.

4 Errors to Break + Fix

  • OOMKilled: Pod limit se zyada memory use kar raha hai. (Fix: Limit barhayen ya app ka memory leak theek karein).
  • Pending: Agar aapki Requests itni zyada hain ke cluster mein koi Node itna farigh nahi hai, toh pod Pending state mein phans jata hai.
  • Quota-exceeded rejections: Agar Namespace quota bhar gaya hai, toh naye pods create hone se inkaar ho jayega.

5 Best Practices (Pro Tips)

  • Hamesha production mein Requests aur Limits zaroor set karein! (Blank mat chorein).
  • Critical workloads (Database, Main API) ke liye hamesha Guaranteed QoS aim karein (Request == Limit).
  • Namespace level par LimitRange aur ResourceQuota hamesha use karein taake koi ek developer pura cluster crash na kar de.

Done-Check

  • Pod ki QoS class visible hai (`kubectl describe pod`), aur aapne practically OOM (Out Of Memory) ko reproduce kar ke samajh liya hai!
