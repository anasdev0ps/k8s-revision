1 Analogy (Samajhne ke liye)

Git: Single source of truth. Jo code ya config Git mein hai, bas wahi sach hai.

ArgoCD: Ek aisa robot jo har waqt Git repo ko dekhta rehta hai. Agar K8s cluster ka haal Git se match na kare, toh ye robot automatically cluster ko fix (heal) kar ke Git jesa bana deta hai.

2 Core Concepts

  • Declarative GitOps: Hum manually kubectl apply nahi karte. Hum sirf files Git mein push karte hain, ArgoCD khud apply karta hai.
  • Application CRD: ArgoCD ek resource banata hai jisme bataya jata hai ke "Ye repo is cluster/namespace par deploy karni hai".
  • Self-heal & Drift detection: Agar koi manual K8s mein ja kar replica change kare (drift), toh ArgoCD foran usay revert (self-heal) kar dega!
  • App-of-Apps: Ek master Argo app jo baqi sari apps ko deploy karti hai (pura cluster ek sath bootstrap karne ke liye).

3 Hands-on Steps

  1. Cluster mein ArgoCD install karein.
  2. Ek Git repo (jisme aapke manifests ya Helm chart hon) ko ArgoCD ke sath connect karein.
  3. Auto-sync on karein. ArgoCD foran YAMLs ko K8s mein deploy kar dega.
  4. Manually K8s dashboard ya kubectl se ek pod delete karein ya replica change karein, aur dekhein ArgoCD usay wapis heal karta hai ya nahi.

4 Errors to Break + Fix

  • OutOfSync loops: Agar Git mein aur K8s mein Mutating Webhooks waja se fark paida ho jaye, toh ArgoCD lagatar usay sync karta rehta hai. IgnoreDifferences laga kar isay fix karein.
  • Sync-wave ordering: Agar DB deploy hone se pehle App deploy ho jaye aur crash ho jaye, toh Sync Waves (`argocd.argoproj.io/sync-wave`) use karein.

5 Best Practices (Pro Tips)

  • Git is Law: Production mein change karne ka wahid rasta Git PR (Pull Request) hona chahiye. (No manual `kubectl`).
  • Code repo aur Config (Manifests) repo ko alag alag rakhein. Is se CI aur CD alag ho jate hain.
  • Auto-Prune ko hamesha ehtiyat se on karein, warna Git se file delete hone par production se app urr sakti hai!

Done-Check

  • Aapne manual K8s change kiya aur ArgoCD ne "Na-manzoor" keh kar usko wapas Git ke jesa kar diya! GitOps in action!
