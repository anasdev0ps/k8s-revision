1 Analogy (Samajhne ke liye)

Error Lab: Yeh ek "Fire Drill" (Aag bujhane ki mashq) hai. Jab production mein aag lage (cluster down ho) toh panic karne ke bajaye aapko theek se pata hona chahiye ke kounsa tool kahan use karna hai.

2 Hands-on: Deliberate Errors (Break & Fix)

Hum in tamam errors ko jan boojh kar trigger karenge, aur phir inko unhi tools se diagnose aur fix karenge:

Error How to trigger (Kese toren) Skill Learned
CrashLoopBackOff Ghalat command lagayen ya liveness probe fail karayen. Restart policy + logs
ErrImagePull Image ka naam ghalat likhein ya private repo bina secret ke dein. Images + imagePullSecrets
OOMKilled Memory limit boht kam (e.g. 10Mi) set karein. Resource limits
Pending CPU request itni ziada maangein jo kisi node ke paas na ho. Scheduling + events
502 / 503 Gateway route mein ghalat port de dein. Gateway ↔ Service ↔ Pod chain
Service unreachable Service ke selectors ghalat dalein (empty Endpoints). Labels / Endpoints mapping

3 Best Practices (Pro Tips)

  • Fixed Triage Order: Hamesha is order mein debug karein:
    get pods ➜ describe ➜ logs ➜ get events ➜ get -o yaml.
  • Agar pod crash ho kar restart ho gaya hai aur naya pod chal raha hai, toh pichle crash wale pod ke logs dekhne ke liye --previous ya -p ka flag use karein: kubectl logs <pod-name> -p.
  • Events check karne ke liye is command se sort karein taake latest error neechay aaye: kubectl get events --sort-by=.lastTimestamp.
