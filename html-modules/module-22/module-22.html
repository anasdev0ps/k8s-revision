1 Analogy (Samajhne ke liye)

Node Upgrade: Yeh aese hai jaise ek chalti hui train ka dabha (carriage) theek karna ho. Pehle aap sab musafiron (Pods) ko us dabhe se nikal kar dosre dabhe mein bhejte hain (Drain), phir us dabhe ka engine theek karte hain (Upgrade), aur phir usay wapas khol dete hain taake naye musafir aa sakein (Uncordon).

2 Core Concepts

  • Version Skew Policy: Kubernetes (N-2) ki policy allow karta hai. Yani kubelet hamesha kube-apiserver se thora purana (maximum 2 minor versions) ho sakta hai, par naya nahi.
  • Upgrade Order: Hamesha pehle Control-plane upgrade hoga, uske baad ek ek karke Worker nodes upgrade honge.
  • Hamesha ek minor version karke upar jayen (e.g., v1.34 se directly v1.36 par nahi ja sakte, pehle v1.35 par jana hoga).

3 Hands-on Steps

  1. OS ke package manager (e.g., `apt`) ki repo minor version ko update karein (pkgs.k8s.io).
  2. Pehle kubeadm upgrade karein.
  3. Control-plane node ko Drain karein: kubectl drain <node-name> --ignore-daemonsets.
  4. kubeadm upgrade apply v1.x.y chalayen.
  5. OS par kubelet aur kubectl upgrade kar ke service restart karein.
  6. Node ko wapas allow karein: kubectl uncordon <node-name>.

4 Errors to Break + Fix

  • Drain Blocked: Agar PodDisruptionBudget (PDB) allow nahi kar raha ke pod delete ho, toh Drain fail ho jayega. PDB theek karein ya pod manually hata dein.
  • Skew Violations: Agar Worker node Control plane se naya version ho gaya, toh cluster break ho sakta hai. Order hamesha theek rakhein.

5 Best Practices (Pro Tips)

  • Upgrade karne se pehle hamesha etcd ka backup le lein. (Agar upgrade fail hua toh cluster wapas lane ke liye zaroori hai).
  • Release notes laazmi parhein, kyun ke Kubernetes purani APIs ko aksar remove kar deta hai (Jaise v1beta1 Ingress remove hui thi).

Done-Check

  • Aapka control-plane aur nodes naye version par upgrade ho chuke hain, aur chalte hue workloads ko koi downtime nahi aaya!
