ConfigMaps & Secrets

Har application ko chalne ke liye kuch settings (jaise PORT number) aur kuch passwords (jaise Database password) chahiye hote hain. Agar hum inhein code ke andar likh dein (hardcode kar dein), toh har environment ke liye naya code likhna padega. Kubernetes in settings ko app se alag karne ke liye **ConfigMaps** aur **Secrets** use karta hai.

1 Analogy

- ConfigMap: Office ke notice board par lagi Sticky Note, jo koi bhi padh sakta hai (e.g., Office timings).
- Secret: Manager ki table ke locked Drawer mein rakha hua document (e.g., WiFi password).

2 Concepts

  • ConfigMap: Non-confidential data (jaise URLs, ports, toggle flags) ko store karne ka tareeqa.
  • Secret: Confidential data (jaise passwords, tokens, SSH keys) ko Base64 mein encode kar ke store karna.
  • Injection Methods: Data ko Pod mein as an Environment Variable (envFrom) dalna ya as a File (Volume mount) lagana.
  • Base64 vs Encryption: Yaad rakhein ke default Kubernetes Secrets encrypted nahi hote, sirf Base64 encoded (scrambled) hote hain!

3 Hands-on Steps

  • Ek ConfigMap banayen: kubectl create configmap app-config --from-literal=PORT=3000.
  • Ek Secret banayen: kubectl create secret generic db-pass --from-literal=password=mysecret.
  • Deployment YAML mein ConfigMap ko as Environment Variable (env) mount karein.
  • Deployment YAML mein Secret ko as a File (volumeMount) attach karein.
  • ConfigMap ki value update karke dekhein ke pod usey foran pick karta hai ya restart ki zaroorat hoti hai.

4 Errors (Jo hum break karke fix karenge)

Hum jaan boojh kar in issues ko create aur fix karenge:

  • Missing Key/ConfigMap: Agar hum YAML mein aisa ConfigMap maangein jo banaya hi nahi, toh Pod CreateContainerConfigError state mein phans jata hai.
  • Secret not mounted: Agar app password dhoond raha hai aur file mount nahi hui, toh application 500 Server Error deti hai.

5 Best Practices

  • CRITICAL: Plaintext Secrets kabhi bhi apne Git repository mein commit na karein!
  • Hamesha "Sealed Secrets" ya "External Secrets Operator" (jaise AWS Secrets Manager ya HashiCorp Vault) use karein production ke liye.
  • Kubernetes cluster par etcd encryption-at-rest enable karein taake data hard-drive par bhi secure rahay.
