1 Analogy (Samajhne ke liye)

Kargo: Ek factory ki "Assembly Line" (conveyor belt) jahan ek item (App version) Dev se chalta hai, usko test kiya jata hai (Gates), aur pass hone par aage Production mein bhej diya jata hai.

2 Core Concepts

  • Kargo vs ArgoCD: ArgoCD sirf 1 cluster ko sync karta hai. Kargo ArgoCD ke upar baithta hai aur batata hai ke "Pehle Dev ko update karo, phir ruk jao, test pass hone par Prod ko update karo".
  • Freight: Ek versioned bundle (jaise Image tag + Helm chart version). Isay bar bar rebuild nahi karte, yahi same box aage jata hai.
  • Stages & Gates: Dev → Stage → Prod. Har stage ke darmiyan Verification gates lagaye jate hain.

3 Hands-on Steps

  1. Cluster mein Kargo install karein.
  2. Ek Warehouse banayen jo Docker registry ko dekhe.
  3. Do Stages banayen (Dev aur Prod).
  4. Dev mein ek Freight (v1.0) promote karein.
  5. Verification set karein, aur uske baad manually ya automatically same Freight ko Prod mein promote karein.
  6. In Stages ko ArgoCD Applications ke sath wire karein.

4 Errors to Break + Fix

  • Promotion blocked: Agar Verification fail ho jaye, toh Kargo Freight ko Prod mein jane se rok deta hai. Pehle code theek karein aur naya Freight banayen.
  • Credentials/registry access: Agar Kargo Warehouse private registry ko na parh sakay toh secret create kar ke attach karein.

5 Best Practices (Pro Tips)

  • Immutable Freight: Jo docker image Dev mein test hua hai, EXACTLY wahi image ID Production mein jana chahiye (Dubara build nahi karna).
  • Production se pehle Automated Gates lagayen, lekin final approval ke liye (manual promotion) button use karein agar zaroorat ho.
  • Kargo har promotion ko Git mein commit karta hai, is liye Audit trail hamesha clean rehti hai.

Done-Check

  • Aapka ek hi artifact (Freight) successfully Dev se hota hua saare gates cross kar ke Production mein poch gaya!
